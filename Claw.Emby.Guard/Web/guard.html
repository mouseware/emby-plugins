History (expired / lifted; used for escalation)

Failed sign-ins

When on, any sign-in attempt with a username that does not exist in Emby bans the address immediately (LAN and whitelisted addresses are still never banned). Off by default; the tries setting above then applies.
Forbidden sign-ins (account not allowed to connect remotely) count as failed sign-ins. A successful sign-in from the same address resets its counter.

Instant-ban usernames

Names that are real Emby users are skipped, so a real user mistyping their password never bans themselves. Only addresses are banned; Emby accounts are never locked.

Failed API calls (401 / 403)

Read from embyserver.txt ("Response 401/403 to <ip>"). Apps with an expired session produce a few 401s, so keep this well above the sign-in threshold.

Ban length (escalation)

Event "Guard: IP address banned". Enable it for your notifier (e.g. email) under Settings → Notifications.
Home and LAN addresses are never filtered by Emby (loopback, 10/8, 172.16/12, 192.168/16, link-local, 100.64/10, IPv6 ULA/link-local and Emby's own "LAN networks"), so Guard never bans them and they don't need to be listed here. Your admin address is not trusted automatically.

Country (optional, MaxMind GeoLite2)

Free GeoLite account at maxmind.com (GeoLite EULA). With both set, Guard downloads GeoLite2-Country, refreshes it weekly and shows a Country column. Clear them to hide the column and delete the database.

Log retention

General

Off = no new bans, and every entry Guard added to Emby's Remote IP filter is removed (entries you typed there yourself stay). Events are still logged. Bans are kept and come back when you switch it on again.
